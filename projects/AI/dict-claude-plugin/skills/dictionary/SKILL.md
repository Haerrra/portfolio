# 데이터 딕셔너리 공인 지표 조회 워크플로우 정의

## Purpose
이 문서는 사용자의 자연어 지표 질문을 딕셔너리 지표명으로 해석하고, 통합 함수 `analytics.metric_catalog.crt_dictionary_tvf` 로 Databricks 에서 조회한 결과를 출처와 함께 표로 답하는 워크플로우를 정의한다.
- 사용자가 `/dictionary <질문>` 으로 부를 때만 작동
- 명령어 호출 = **딕셔너리 공인값** 요청으로 간주
- 산식을 새로 작성하지 않음
- 모든 답 첫 줄에 [출처 표시](#source-label--모든-답변의-첫-줄-필수) 필수

질문: $ARGUMENTS

- 질문이 비어 있으면 조회 대상을 묻고 예시 2개 제시
    - "지난주 29CM 거래액"
    - "9월 무신사 DAU 주별로"

## Principles
충돌하면 아래 순서 우선.
1. **정의는 함수 COMMENT 가 정본**
    - 이 스킬의 문서와 다르면 COMMENT 를 따르고, 문서 오류를 사용자에게 알림
2. **함수에 없는 지표는 만들지 않음**
    - 원천 테이블 직접 집계 금지
    - 다른 채널 값으로 대체 금지
    - → [범위 밖](references/out_of_scope.md)
3. **가정하지 않음**
    - 채널이 없거나 표현이 애매하면 조회 전에 질문
4. **정의 차이를 숨기지 않음**
    - 기준이 둘인 지표는 나란히 제공
    - 채널 비교 시 차이 명시

## Databricks Connection Rules
세션에 Databricks SQL 실행 도구(MCP · CLI · REST 등 이미 쓰는 경로)가 없으면 다른 절차보다 먼저 **연결 안내 후 중단**.
- 값 · 정의 · 함수 본문 질문은 "연결한 뒤 다시 물어 주시면 바로 조회해 드립니다"로 보류
    - SQL 대신 제공 금지
    - 문서 내용으로 정의 대신 설명 금지
- SQL 은 사용자가 "SQL 만 달라"고 분명히 요청할 때만 제공
- 토큰을 대화창으로 받지 않음

## First Turn
### 묻지 않고 스스로 확인
- 지표가 그 채널 [색인](references/metric_index.md)에 있는지
- 그 지표의 채워지는 주기
- 기간 끝이 어제 이전인지 (오늘 이후는 미적재)
- 조회 하한 ([채널 차이](references/channel_differences.md) §6)

### 사용자에게 한 번에 질문
요청에 이미 있는 항목은 묻지 않음.
1. **채널** — 29CM / 무신사 / 글로벌 / 오프라인
    - 요청 문장에 채널이 없으면 **무조건** 질문
    - 작업 폴더 · 이전 대화 · 사용자 소속으로 짐작 금지
2. **기간** — 시작일 · 종료일
    - "지난주" · "지난달"은 오늘 기준 날짜로 바꿔 확인
    - 연도 없이 말하면 올해(아직 안 온 날짜면 작년)로 잡고 답 머리말에 명시
3. **주기** — day / week / month
    - 지표가 특정 주기에서만 채워지면 그 사실을 먼저 안내
4. **지표** — 아래 Expression → Metric 에서 **되묻기**로 판정된 것만 후보와 함께 질문

## Expression → Metric
사용자 표현은 [동의어 사전](references/synonyms.md)으로 지표명에 변환. 판정은 3가지.

| 판정 | 조건 | 행동 |
|------|------|------|
| 확정 | 후보가 하나 | 바로 조회. 답 머리말에 "○○ 은 `지표명` 으로 조회" 명시 |
| 병기 | 같은 계열이라 나란히 보면 오해가 없음 (GMV · GGMV 기준 등) | 되묻지 않고 모두 조회해 열로 나란히 제공 |
| 되묻기 | 후보끼리 뜻이 다름 ("매출", "전환율", "리텐션" 등) | 조회하지 않고 후보와 반 줄 정의를 보여 주며 선택 요청 |

- 사전에 없는 표현은 색인과 직접 비교
    - 후보 2개 이상 → 되묻기
    - 후보 없음 → 범위 밖 확인
- 표현에 기준이 붙어 있으면("취소 반영", "원주문 기준") 그 기준 하나만 제공
- 채널 · 기간 · 주기 질문과 지표 되묻기는 **한 메시지에 모아** 질문 (여러 번 왕복 금지)

## Workflow Steps

1. 채널 · 지표명 확정
   - 그 채널 색인에 없으면 [범위 밖](references/out_of_scope.md)으로 이동

2. SQL 선택
   - 질문 꼴에 맞는 SQL 을 [호출 패턴](references/call_patterns.md)에서 선택
       - 기간별 표 (§1)
       - 두 채널 (§2)
       - 기간 비교 (§3)
       - month 전용 (§4)

3. 조회 실행
   - `p_metrics` 에 물은 지표만 넣어 실행

4. 검산
   - 결과 제공 전 [호출 패턴 §6](references/call_patterns.md) 검산 한 줄 실행

5. 답변
   - **표 + 해석 + 근거** 순서로 답변

## Special Cases
### 정의 질문
- 함수 COMMENT 를 읽어 답변 ([호출 패턴 §7](references/call_patterns.md))

### 함수에 없는 축 (브랜드 · 카테고리 · 국가별)
- [호출 패턴 §8](references/call_patterns.md)대로 원본 함수 본문에서 출발
- 결과에 `함수 변형 · 딕셔너리 공인값 아님` 명시

### 권한 오류 (`PERMISSION_DENIED`)
- 원천 직접 집계로 대체 금지
- team 카탈로그 접근 권한이 필요하다고 안내 후 중단

### 시간 초과
- [호출 패턴 §5](references/call_patterns.md) 준수
- "데이터 없음"으로 보고 금지

### 통합 함수 없음 (`UNRESOLVABLE_TABLE_VALUED_FUNCTION` · 함수 없음 오류)
- 같은 값을 주는 원본 함수를 직접 호출 (값 · 정의는 통합 함수와 동일)
- 함수: `analytics.metric_catalog.crt_<채널>_dictionary_<유형>_tvf(p_period, p_start_dt, p_end_dt)`
    - 유형은 [색인](references/metric_index.md)의 유형 열로 결정
    - 커머스 `commerce` · 프로덕트 `product` · 마케팅 `marketing` · 광고사업 `ads` · 페이먼츠 `payments` · 물류·운영 `logistics`
- 지표 = 반환 열 이름
    - 필요한 열만 선택
    - 열 이름에 공백 · 괄호가 있으면 백틱으로 감쌈
- 원본 함수에도 없으면(물류·운영 등 미배포) 다른 경로로 집계 금지
    - "함수가 배포되지 않아 조회할 수 없다"고 안내
- 출처 표시는 실제로 부른 원본 함수로 작성
    - 대신 호출했다는 설명은 답 끝 근거에 한 줄만

## Source Label — 모든 답변의 첫 줄 (필수)
사용자가 이 스킬의 답과 다른 경로(Databricks MCP 로 테이블을 직접 조회한 답 등)를 구분할 수 있어야 함.
- 답의 종류에 맞는 표시를 **첫 줄에 그대로** 작성
- 표시 없이 값 제공 금지

| 답의 종류 | 첫 줄 |
|------|------|
| 함수로 조회한 값 | `📘 딕셔너리 공인값 · crt_dictionary_tvf('<채널>', '<주기>', <시작일>, <종료일>, [<지표>, …])` |
| 통합 함수가 없어 원본 함수로 조회한 값 | `📘 딕셔너리 공인값 · crt_<채널>_dictionary_<유형>_tvf('<주기>', <시작일>, <종료일>) → <지표> 열` |
| 지표 정의 · 산식 | `📘 딕셔너리 정의 · 함수 COMMENT 기준` |
| 함수 본문을 바꿔 다른 축으로 뽑은 값 (§8) | `⚠️ 함수 변형 · 딕셔너리 공인값 아님 · 원본 <함수명>` |
| 범위 밖이라 원천에서 뽑아 달라고 다시 요청받은 값 | `⚠️ 딕셔너리 지표 아님 · 정의 미확인` |

- 되묻기 · 연결 안내 · 범위 밖 안내처럼 값을 주지 않는 답에는 표시 생략
- 두 채널 또는 두 번 호출한 값을 한 표에 넣으면 호출을 모두 기재
- 같은 대화의 후속 질문("그럼 전주랑 비교해 줘")에도 동일 적용

## Output Rules
- 출처 표시 다음 줄에 채널 · 주기 · 기간 · 조회한 지표명을 사람이 읽는 말로 작성
    - 동의어로 변환한 지표면 "○○ 은 `지표명` 으로 조회" 함께 기재
- 비율 단위(소수 / %)와 금액 단위를 표 머리말에 명시
- GMV 기준과 GGMV 기준은 지표명 그대로 두 열에 배치 → [해석 주의 §1](references/interpretation_notes.md)
- 두 채널을 한 표에 넣으면
    - 열 머리말에 채널 명시
    - [채널 차이](references/channel_differences.md)의 해당 차이를 표 밑에 기재
- NULL ≠ 0
    - 주기 · 적재 범위 때문에 비었으면 이유 기재 → [해석 주의 §2](references/interpretation_notes.md)

## ⚠️ Safety Rules
- 채널 간 방문자 · 구매자 합산 금지
- 글로벌 GMV 를 다른 채널 GMV 와 말없이 합산 금지
- 비율 단위 혼용 금지 (이미 % 인 값을 다시 ×100 금지)
- 누적값 · 일별 distinct 값을 SUM 해서 주간 · 월간 생성 금지
- `p_period` 에 `'daily'` · `'weekly'` 같은 값 사용 금지
