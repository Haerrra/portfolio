# 사내 정책 문서 대조 기록 (요약)

KPI 정의와 TVF를 만들기 전에, 가격·할인 정책 문서에 적힌 정의가 실제 데이터와 맞는지 확인했다.
구체적인 정책 기준값·사내 문서 위치·원천 테이블은 공개 범위에서 제외하고, 무엇을 확인했고 결과가 설계에 어떻게 반영됐는지만 남긴다.

표기: [문서] 정책 문서에 적힌 내용, [실측] 읽기 전용 쿼리로 확인한 값, [추론] 둘을 바탕으로 한 해석.

## 1. 탐색한 정책 범위 [문서]

| 영역 | 확인한 내용 |
|---|---|
| 가격 | 정상가·판매가·현지 통화 가격의 산식, 국가별 가격 배율과 환율 적용 순서, 라운딩 규칙 |
| 세일 | 세일 유형별 우선순위(프로모션 > 기간 > 상시), 지역×상품당 1개 적용 원칙, 저장 시간대 |
| 할인 순서·쿠폰 | 정상가 → 세일가 → 상품쿠폰 → 장바구니쿠폰 → 적립금 순서, 쿠폰별 계산 기준 금액 |
| 쿠폰 적용 가능 여부 | 상품×국가별 쿠폰 가능 여부를 정하는 우선순위(관리자 설정 > 상품군 예외 > 기본 정책) |
| 할인 부담 | 세일·쿠폰 할인액을 플랫폼과 파트너가 나누는 구조, 매입 형태(1P/3P)별 차이 |

## 2. 실데이터 대조에서 찾은 문제 [실측]

| 유형 | 내용 | 설계 반영 |
|---|---|---|
| 시간대 | 문서상 UTC로 알려진 주문 시각 컬럼이 실제로는 KST였다. 외부 기준점(GA4 이벤트의 UTC epoch)과 대조해 컬럼별로 판정했다. 가입 시각은 UTC, 찜 시각은 KST로 서로 달랐다. | KPI 정의·TVF·Genie 지침에 컬럼별 시간대를 명시하고, 가입→첫 주문 전환 기간처럼 두 컬럼을 같이 쓰는 지표에는 변환 규칙을 추가 |
| 쿠폰 유효기간 | 쿠폰 종료 시각을 KST 값으로 보고 비교하면 실제 종료 시점과 약 18시간 어긋났다. | 쿠폰 스냅샷 함수의 비교 기준을 별도로 정리하고, 한계를 함수 주석과 Genie 안내 문구에 명시 |
| 세일 원천 누락 | 기존 세일 원천 테이블이 세일 시스템 개편 이후의 세일을 상당 부분 반영하지 못했다. 대체 원천 후보 4종을 검증해 가장 적합한 후보를 골랐다. | 판매중 상품 스냅샷 TVF의 한계로 기록, 대체 원천 전환은 후속 과제로 분리 |
| 쿠폰 적용 가능 여부 | 쿠폰 스냅샷이 상품별 쿠폰 가능 여부 정책을 반영하지 않아 쿠폰 보유율이 과대 계산될 수 있었다. | 보유율·부담률 지표에 해석 주의 문구 추가 |
| 금액 차이 설명 | 원화 가격과 현지 통화 가격의 차이를 가격 배율만으로 설명하던 주석이 있었는데, 실제로는 배율과 환율 두 단계였다. | 관련 주석과 예시 SQL 설명 수정 |

## 3. 배운 점

- "운영 마트와 결과가 일치한다"는 검증은 기존 로직을 재현했다는 뜻일 뿐, 정의가 맞다는 근거가 되지 않는다.
- 시간대처럼 문서와 실제가 다를 수 있는 속성은 같은 테이블 안에서 비교하면 순환 논증이 되기 쉽다. 외부의 독립적인 기준점과 대조해야 판정할 수 있다.
- 부담 주체처럼 데이터만으로 확정할 수 없는 항목은 [추론]으로 표시하고, 확인 전까지는 지표로 분해하지 않는 원칙을 유지했다.

검증에 쓴 스크립트는 `../validation_queries/`에 있다(시간대 교차검증: `verify_tz_*.py`).
